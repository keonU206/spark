## 1. 가장 중요한 발견

### 1-1. 이 앱은 웨이트 트레이닝 앱이 아니다

초기 가정(세트/무게/1RM/볼륨 추적)은 **시안과 맞지 않는다.**

시안이 실제로 다루는 것:

| 항목 | 시안의 실제 내용 |
|------|------------------|
| 운동 단위 | `좌우 8~10회 · 2세트 · 4분` — **무게 입력란이 없음** |
| 운동 종류 | 스쿼트, 런지, 스트레칭 — **홈트레이닝/스트레칭 중심** |
| 통계 지표 | 총 운동 횟수(124회), 총 운동 시간(61시간), 연속 출석(14일), 완료 루틴(18회), 건너뛴 운동(3회), 평균 운동 시간(28분) |
| 없는 지표 | 볼륨, 1RM, 중량 추이 — **시안 어디에도 없음** |

→ **핵심 가치는 "기록의 정밀도"가 아니라 "매일 하게 만드는 것"(streak + 소셜 압박)** 이다.

### 1-2. 소셜 독려가 부가 기능이 아니라 앱의 축이다

`홈`, `커뮤니티`, `모임 상세` 세 화면 모두 절반 이상이 **타인의 운동 현황 + 찌르기 버튼**으로 채워져 있다.

- 홈: "친구의 운동 현황" → `깨우기 🖐` 버튼
- 커뮤니티: "친구의 운동 현황" → `재촉하기 🔥` 버튼
- 모임 상세: "구성원 운동 현황" → `잡도리` 버튼

→ 모임/커뮤니티를 빼면 앱의 정체성이 사라진다. **포함 결정은 타당하다.**

## 2. 미확정 사항 (구현 전 반드시 결정)

### 2-1. ⚠️ 디자인 방향이 두 갈래로 공존한다

캔버스 메모: *"채린 / 승연 / 목요일 오전까지 왼쪽 오른쪽 / 자기가 맡은 거 다 해오세용"*
→ 두 사람이 나눠 작업 중이며, **컬러 시스템이 통일되지 않았다.**

| 화면 | node | 방향 |
|------|------|------|
| 홈 | `56:636` | **초록** 계열 (`#22C55E` 추정), 탭 아이콘 초록, 버튼 초록 |
| 모임 상세/캘린더 | `69:1198` | **초록** 테두리 + **검정** 버튼 |
| 운동 | `61:768` | **주황** 계열 (`#FF5722` 추정), 아이보리 배경 |
| 커뮤니티 | `77:1506` | **주황** 계열 |

같은 "친구의 운동 현황" 섹션이 홈(초록)과 커뮤니티(주황)에 **중복 존재**한다.
→ 두 사람이 같은 기능을 각자 그린 것으로 보인다.

**영향: 디자인 토큰 정의가 통째로 달라지므로, 이걸 확정하기 전엔 Phase 1을 시작할 수 없다.**

### 2-2. ⚠️ 같은 기능의 이름이 3개다

`깨우기` / `재촉하기` / `잡도리` — 모두 "운동 안 한 사람 찌르기" 기능.
→ API 이름(`nudge`)은 통일하되, UI 라벨은 확정 필요.

### 2-3. 시안 자체가 미완성

캔버스 메모: *"나머지 페이지 마무리 / 디자인 짜잘한 거 맞추기 / 로고·네이밍 → 네이밍 정하면 앱 내 이름들 바꾸기"*

- 앱 이름 미정 (코드상 `spark`로 진행하기로 결정)
- 로고 미정
- 일부 프레임은 이름이 `Frame`, `Frame 1707481821` 등 미정리 상태
- `(수정 필요) 하단바` 라는 이름의 프레임 존재 (`56:648`)

## 4. 판독한 화면 상세

### 4-1. 홈 (`56:636`, 초록 방향)

```
Header: "홈"
├─ 오늘의 추천 운동            [더보기 >]
│  "{닉네임}님을 위해 오늘의 운동 루틴을 추천드려요"
│  └─ 캐러셀 (인디케이터 3개)
│     └─ 카드: [썸네일] 운동 이름 / "5개 운동 · 약 20분" / [운동하기]
├─ 친구의 운동 현황            [더보기 >]
│  └─ 리스트: [아바타] 닉네임 [배지] "1분 전"
│              "1.01km / 경기 광명"          ← 거리 + 지역
│     비활성 친구: "최신 러닝 기록이 없어요.." + [깨우기 🖐]
└─ 내 운동 현황               [더보기 >]
   └─ 주간 요일 체크 (월~일, 완료=초록 체크 / 미완료=회색)
Footer: 홈 · 운동 · 독려 · 마이
```

> ⚠️ "1.01km / 경기 광명", "최신 **러닝** 기록" → **위치·거리 기반 러닝 데이터**가 등장.
> 스트레칭 중심인 운동 탭과 성격이 다르다. 레퍼런스 잔재인지 실제 기획인지 확인 필요.

> → 카톡 단톡방식 네이밍. 모임명이 없으면 멤버명으로 대체하는 규칙으로 보임.

## 5. 추론한 도메인 모델

```
User ──< FriendEdge >── User
 │
 ├──< RoutineSession >──< SessionExerciseLog >── Exercise ──> ExerciseCategory
 │         (운동 기록)                                   (종목 DB)
 ├──< Routine >──< RoutineExercise >── Exercise
 │    (내 루틴 / 추천 루틴)
 ├──< UserBadge >── Badge
 ├──< StreakRecord >  (연속 출석)
 ├──< GroupMember >── Group ──< GroupFeedPost >
 │                      └──< GroupAttendance >
 └──< Nudge >  (깨우기/재촉하기/잡도리 — 발신자·수신자·시각)
```

핵심 파생값 (백엔드 계산 vs 프론트 계산 결정 필요):
- `streakDays` — 연속 출석일
- `weeklyAttendance[7]` — 주간 요일별 완료 여부
- 월간 집계 — 완료 루틴 / 건너뛴 운동 / 평균 시간

→ **백엔드 계산 권장.** 프론트가 전체 기록을 받아 계산하면 데이터량·정합성 문제가 생긴다.
